## การวิเคราะห์บทที่ 4 `ana.js`

- **วิธีโนด** `ANA.nodal(ckt, meta)`: โนด = เน็ตจาก `ckt.topology()` · แหล่งจ่ายแรงดันที่ต่อจากโนดที่รู้ค่า (เริ่มจากโนดอ้างอิง ต่อเป็นทอดได้) ทำให้โนดอีกด้านรู้ค่า · แหล่งจ่ายแรงดันระหว่างสองโนดที่ไม่รู้ค่ารวมเป็นซูเปอร์โนด (union-find) ได้ KCL ของเส้นรอบ + สมการเงื่อนไข v₊ − v₋ = V · ตัวต้านทานอนุกรมใน `meta.series` รวมก่อน (โนดกลางไม่เป็นตัวแปร) · พจน์ KCL เรียงตามลำดับชิ้นส่วนในวงจร · ตัวต้านทานที่ 1/R เป็นจำนวนเต็ม (1/3, 1/6 Ω) เขียนแบบ G(v − v)
- **วิธีเมช** `ANA.mesh(ckt, meta)`: หาเมชจากรูปเอง: ทุกชิ้นส่วนเป็นขอบสองทิศ ไล่หน้าของกราฟระนาบโดยเลี้ยวขวาให้มากที่สุดที่ทุกจุด หน้าที่มีพื้นที่เชือกผูกรองเท้าเป็นบวก (ตามเข็มนาฬิกาบนจอ) คือเมช ตั้งชื่อด้วยจุด `at` ที่อยู่ในหน้า · แหล่งจ่ายกระแสที่อีกฝั่งเป็นหน้านอกทำให้เมชรู้ค่า · แหล่งจ่ายกระแสระหว่างสองเมชรวมเป็นซูเปอร์เมช (ขอบเขตของหลายหน้าเดินด้วย h.next และกระโดด twin.next เมื่อเจอขอบภายใน) · KVL เริ่มที่จุดล่างซ้ายเดินตามเข็มนาฬิกา ได้ลำดับพจน์ตรงกับ Hayt และเฉลย
- ค่าชิ้นส่วนแปลงเป็นเศษส่วนด้วย `ANA.FX` (หาเศษส่วนตัวส่วน ≤ 10000) เพราะ `ALG.Frac.of` ปัดเป็นทศนิยม 6 ตำแหน่ง (1/3 Ω จะผิด)
- `meta.extras(S)` คืน `[{t: [ไทย, English], tex, glow, note}]` โดย `S.v(node)` / `S.i(name)` เป็นเศษส่วนแม่นตรง
- หน้ารูปแบบใหม่: `CH4.problem(n, key, 'nodal' | 'mesh', { ask: sim => ({fields, check}), answer, drill: true })` (ดูหน้า 4.1) ก่อนวิเคราะห์จะตั้ง `ANA.colW` = ความกว้างของคอลัมน์เฉลย สูตรจึงจัดบรรทัดตามที่ว่างจริง (มือถือ จอกว้างที่แบ่งสองคอลัมน์ หรือคอลัมน์เดียวที่ 1000 px) ส่วนชุดทดสอบไม่มี KaTeX จึงไม่ตัดบรรทัด

- กระดาษจดในห้องหน้าเดียวที่ใช้กับสองโจทย์ (เฉลยสไลด์หน้า 7 หาทั้ง P และ Q, S) ให้แสดงที่โจทย์แรกครั้งเดียว แล้วโจทย์ที่สองลิงก์กลับ (ไม่ตัดแบ่งรูปเพราะผลคือรูปเดียวกันโผล่สองที่)
- **เพิ่มสิ่งที่ส่งออกใน assets ต้องเปลี่ยน `?v=` ทันที** (บทที่ 9): หน้าที่โหลดไฟล์ `?v=` เดิมไว้แล้วจะได้ไฟล์เก่าจาก cache เช่น `CH9.ov` เป็น undefined ทั้งที่ไฟล์บนดิสก์มีแล้ว
- วงจรสามเฟส (กว้างราว 14 หน่วยกริด) ในการ์ด 780 px แบบ wide ของ Board เหลือแค่ครึ่งการ์ด ป้ายเล็กและชนกัน จึงตั้ง `wideAt: 1e9` ให้ใช้แบบ `mid` ทุกความกว้าง
- โจทย์ที่ถามอิมพีแดนซ์ ห้ามแสดงค่าบนวงจรตั้งแต่ขั้นแรก (บอกคำตอบ) ใช้ spec สองชุดที่ต่างกันแค่ป้าย ("? Ω") และต้องมีโนดขอบชุดเดียวกัน ไม่อย่างนั้นวงจรเปลี่ยนขนาดตอนค่าโผล่
- `\text{${t(…)}}` ใน `String.raw` นับวงเล็บปีกกาให้ดี: เกินมาหนึ่งตัวทำให้ KaTeX ขึ้นข้อความดิบทั้งบล็อก (tests.html มีเทสต์นับวงเล็บของทุกขั้นในบทที่ 9)
- คำอธิบายความผิดของเฉลยในห้องวางไว้ในกล่องพับเดียวกับภาพเฉลย ไม่วางใต้ภาพโจทย์ (บอกคำตอบก่อนนักศึกษาลองทำ)

## การเขียนหน้าใหม่ (สำหรับบทที่ 2 เป็นต้นไป)

คัดลอกโครงของ `ch1_1_linear.html`: head (ฟอนต์ + KaTeX + assets) → `h1` สองภาษา → `.equation-box` → `p.sub` → `.layout` (canvas + `aside.panel`) → `.legend` → การ์ด → `.notes` (ลองทำดู 3 ใบ) → `nav#mc-nav` แล้วเพิ่มรายการใน `assets/stops.js` (ลบ `soon: true`)

มาตรฐานความอ่านง่าย (ปรับเมื่อ 4 ต.ค. 2569 ตามคำขอของผู้สอน):
- **โหมด EN ต้องไม่มีภาษาไทยเลย** (ยกเว้นปุ่ม "ไทย") ทุกข้อความใน JS ต้องผ่าน `t('ไทย','English')` / `MC.t(...)` ข้อความใน HTML ต้องแยก `data-l="th"` / `data-l="en"` และหัวเรื่อง `h1` ภาษาอังกฤษห้ามมีบรรทัดรองภาษาไทย ตรวจด้วยสคริปต์สแกน DOM ในโหมด EN และตัวตรวจแบบสแตติกที่หา string ภาษาไทยที่ไม่ได้อยู่ในคู่ภาษา
- ตัวอักษรเนื้อหา 17 px สีเข้ม (ไม่ใช้สีเทาจางกับย่อหน้าหลัก) ข้อความบนภาพวงจรอย่างน้อย 11–12 px
- ทุกหน้ามีกล่อง **"ประเด็นสำคัญของหน้านี้" / "Key points"** 4–5 ข้อ ขึ้นต้นด้วยตัวหนา และทำตัวหนาที่ข้อสรุปในการ์ด "ลองทำดู"
- **สมการ**: ทุกขั้นที่มีหลายบรรทัดใช้ `aligned` จัดเครื่องหมาย = ให้ตรงกัน คำตอบสุดท้ายใส่ `\boxed{}` ระบบสมการใช้ `ALG.texSystem` ให้ตัวแปรเรียงเป็นคอลัมน์ การแทนค่าย้อนกลับใช้ `ALG.backSub(...).chain(unit)` ฟังก์ชันแยกช่วงใช้ `cases`

กับดักที่เจอแล้ว:
- `ui.radio`/`ui.buttons` สร้างปุ่มที่ใช้ `id` ตามรายการ ห้ามซ้ำกับ id ขององค์ประกอบอื่นในหน้า (เคยตั้งปุ่ม `id: 'steps'` ชนกับ `<ol id="steps">`)
- เนื้อหาใน `.steps li` ต้องห่อด้วย `<div>` ตัวเดียว (li เป็น grid สองคอลัมน์)
- KaTeX ซ่อน MathML ไว้ด้วย `position:absolute` จึงหลุดออกจากกล่องที่เลื่อนแนวนอนได้ ทำให้หน้ากว้างเกินจอมือถือ แก้ด้วย `.equation-box, .eqcard, .katex-display {position:relative}` และ `.eqcard {overflow-x:auto}` (ตรวจทุกหน้าที่ความกว้าง 375 px) · กล่องที่ใส่ `style="overflow-x:auto"` เองในหน้า (ตารางหน้า 6.3, 2.2, 5.3) ต้องมี `position:relative` ด้วย (หน้า 6.3 ภาษาไทยเคยกว้างเกินจอ 55 px ที่ 375 px แก้แล้ว 4 ต.ค. 2569)
- `<details>` มี `<summary>` ได้ตัวเดียว ถ้าต้องสองภาษาให้ใส่ `<span data-l>` สองอันในตัวเดียว
- อย่าใช้ `animation-fill-mode: both` กับสิ่งที่ต้องมองเห็น แผงเบราว์เซอร์ที่ซ่อนอยู่อาจไม่เล่นแอนิเมชันและค้างที่ opacity 0
- เขียนโค้ดหน้าใน `document.addEventListener('mc:ready', …)` เพราะ KaTeX โหลดแบบ defer
- ใน LaTeX ใช้เครื่องหมายลบ ASCII และใส่วงเล็บปีกกามุมติดลบ `\angle{-53.13^\circ}`
- ค่าตั้งต้นของวงจรเลือกให้คำตอบเป็นจำนวนเต็มเพื่อให้นักศึกษาตรวจด้วยมือได้
- ใน template literal ธรรมดา (ไม่ใช่ `String.raw`) `\c` กลายเป็น `c` เช่น `^\circ` ออกมาเป็น "60^c irc" ต้องเขียน `^\\circ` หรือใช้ `` R`...` `` (บทที่ 8 เจอใน `angT`)
- จอกว้าง ป้ายชื่อของแหล่งจ่ายที่อยู่ซ้ายสุด/ขวาสุดล้นกล่องวงจร `CH8.Board` จึงเติมโนดล่องหนด้วย `CH8.margins` · บนจอแคบ หัวกราฟที่ยาวทำให้ค่าที่เคอร์เซอร์หายไป ให้หัวกราฟเป็นฟังก์ชัน `bd => bd.narrow ? 'สั้น' : 'ยาว'` · สามเหลี่ยมหลายรูปบนมือถือใช้ป้ายสั้น (S₁, S₂, S) แล้วใส่ตัวเลขในแผงด้านข้าง
- ป้ายของชิ้นส่วนที่วางเฉียง (โหลดวาย/เดลตา) ไม่ได้รับขอบจาก `shortLabels`/`CH8.margins` ซึ่งดูเฉพาะชิ้นส่วนแนวตั้ง จึงต้องเติมโนดล่องหน `_padL`/`_padR` เอง (`CH9.short` ลบออกบนมือถือ)
- วงจรที่กว้างมาก (บ้าน 5 กิ่ง) บนมือถือต้องจัดใหม่ให้แคบลง (`spec(..., {short: true})`) เพราะตัวอักษรบน canvas ไม่เล็กกว่า 11.5 px ป้ายจึงโตกว่ากริด
